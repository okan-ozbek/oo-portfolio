## Run locally

Install Node.js 22.13.0 or newer, extract the ZIP, and open a terminal in its
`okan-portfolio` directory:

```sh
npm ci
npx vite
```

Open the local URL printed by Vite. Stop the development server with Ctrl+C.

To build the production application:

```sh
npx vinext build
```

These commands use the same installed Vite/Vinext tools as the project scripts.
The original `npm run build` and `npm run install:ci` scripts also include
Linux-specific utilities; see the original `README.md` for those details.

## Where to make changes

| File | What it controls |
| --- | --- |
| `app/portfolio-content.ts` | Résumé copy, results, roles, technology groups, contact details, and navigation labels |
| `app/page.tsx` | Page layout, section order, featured Radish project, interests, and contact area |
| `app/globals.css` | Graphite/lime palette, typography, spacing, canvas clipping, and responsive layouts |
| `app/wave-canvas.tsx` | WebGL ribbon background, motion speed, pause controls, and reduced-motion behavior |
| `app/site-navigation.tsx` | Desktop/mobile navigation, reading progress, and section reveal transitions |
| `app/layout.tsx` | Page title, description, and favicon settings |
| `public/icons/` | Local technology SVGs and their Devicon license |
| `public/images/` | Original artwork assets retained in the repository |

The display font is Manrope; body copy uses DM Sans, and technical labels use
IBM Plex Mono. Google Fonts loads these in the browser. The canvas animation is
generated by code, with reduced-motion support and per-panel pause controls.

## Restore the Git repository

If you downloaded `okan-portfolio-repository.bundle`, you can clone it locally
with the full project history:

```sh
git clone okan-portfolio-repository.bundle okan-portfolio
cd okan-portfolio
```

Choose a different destination folder if you already extracted the source ZIP.
The bundle is a portable Git repository; it contains no repository access token.
After cloning, you can add your own GitHub, GitLab, or other remote and push there.

## Hosting and project structure

The application uses React, TypeScript, Tailwind CSS, Vite, and Vinext, with a
Cloudflare Worker entry point. It is an application source export, not a static
HTML export. Deployment to a different service needs a compatible runtime and
that service's configuration.

The original Sites configuration is retained so the ZIP matches the published
source. The portfolio does not use a database or require application secrets for
its page content. Optional authentication and database starter modules are also
retained as part of the original project.

Installed dependencies, generated builds, local caches, and Git authentication
credentials are not included. Install dependencies using the supplied lockfile.
The application files in this working copy have changed from the original export
commit listed above.

The published production build and scoped application TypeScript check passed.
The starter's full-project TypeScript check separately requires its Cloudflare
runtime type declarations.
